# КЛЮЧ → Wayback Machine: знімки публічних сторінок

Робочий інструмент розробки: знімки публічних сторінок key.chl.kiev.ua для контролю
стану продакшну в період відключень електроенергії.

Кожні 4 години GitHub Actions перевіряє доступність сайту і надсилає порцію сторінок
у Save Page Now (Internet Archive). Сторінки з `priority-urls.txt` перезнімаються щодня,
решта сайту — по колу раз на 30 днів. Працює на серверах GitHub, тому:
- не потребує доступу до продакшн-сервера;
- не зупиняється, коли в Києві немає світла — просто пропускає запуск, якщо сайт недоступний.

## Що це зберігає і чого НЕ зберігає

| ✅ Зберігає | ❌ Не зберігає |
|---|---|
| Публічні сторінки як їх бачить читач (текст, зображення, обкладинки) | Базу даних (зв'язки графу як дані, неопубліковані чернетки) |
| Докази: що, коли й за якою адресою було опубліковано | Оригінали медіа в архівній якості |
| Копію поза Україною, незалежну від установи | Адмінку, кабінети, персональні дані користувачів (виключено свідомо) |

Це **публічний шар збереження**, не заміна бекапу БД (див. `preservation-policy.md`).

## Облікові записи

| Що | Де | Хто керує |
|---|---|---|
| Акаунт Internet Archive | archive.org, адреса `archive@chl.kiev.ua` | Група Google Workspace `archive@` — власники групи |
| Цей репозиторій | GitHub, організація `chl-kiev-ua`, репозиторій `key-wayback` | Власники організації |
| Ключі API архіву | Секрети репозиторію `IA_ACCESS_KEY`, `IA_SECRET_KEY` | Власники організації |

Пароль акаунта archive.org і ключі API зберігаються в менеджері паролів, доступному власникам групи `archive@`.

## Налаштування (одноразово)

1. **Ключі архіву.** Увійти на archive.org під `archive@chl.kiev.ua`
   → https://archive.org/account/s3.php → згенерувати Access key і Secret key.
2. **Репозиторій.** `chl-kiev-ua/key-wayback`, публічний.
   Публічний — бо там безлімітні хвилини Actions; секретів у коді немає, журнал містить лише публічні URL.
3. **Секрети.** Settings → Secrets and variables → Actions → New repository secret:
   `IA_ACCESS_KEY`, `IA_SECRET_KEY`.
4. **Перший запуск.** Actions → «Архівування КЛЮЧа…» → Run workflow → `dry_run = 1`:
   переконатися, що список сторінок правильний. Потім запустити з `dry_run = 0`.

## Якщо хтось із доступом залишає установу

1. Прибрати людину з групи `archive@` і з організації `chl-kiev-ua`.
2. Змінити пароль archive.org.
3. На archive.org/account/s3.php перевипустити ключі й оновити обидва секрети репозиторію.

## Звідки береться список сторінок

1. `priority-urls.txt` — завжди першими.
2. `seeds/` — будь-які CSV/TXT, де трапляються адреси key.chl.kiev.ua
   (напр. експорт звіту «Сторінки» з Search Console — просто покласти файл у папку).
3. `sitemap.xml` сайту, а якщо його немає — обхід сайту по посиланнях.

Порядок: пріоритетні → ще жодного разу не архівовані → найдавніше архівовані.
Сторінки зі свіжим знімком (до 30 днів) архів пропускає сам.

## Як перевірити, що працює

- `archive-log/captures.csv` — журнал: дата, URL, статус, посилання на знімок.
- `archive-log/availability.csv` — журнал доступності: кожні 4 години «up» або «down»
  з причиною. Це фактичний запис того, коли сайт був недоступний.
- Якщо запуск червоний з «САЙТ НЕДОСТУПНИЙ» — GitHub надішле лист.
  Це водночас найпростіший сигнал моніторингу доступності КЛЮЧа.

## Обмеження

- Архів має денні ліміти захоплень для акаунта; при досягненні скрипт зупиняється
  і продовжує в наступному запуску.
- Сторінки з `?query=` / `?page=` пропускаються (щоб не плодити дублі).
- Знімок показує сторінку як вона виглядала; інтерактив (Ріка Часу на D3, пошук) у архіві може не працювати.
